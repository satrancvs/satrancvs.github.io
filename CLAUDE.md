# Satranç vs. (satranckahvesi.github.io)

React + Vite + Tailwind site, deployed to GitHub Pages from `main` (`.github/workflows/deploy.yml`) at the root of
https://satrancvs.com. Articles live in `src/data/articles.json` (metadata) and `src/content/*.md` (body).

## Read this before touching chess rendering
**`docs/chesspublica-quirks.md`** documents the undocumented ChessPublica behavior the old site (`satranckahvesi-eski`)
had to work around. Read it before changing anything that involves ChessPublica: `public/chesspublica/*` (a patched local
copy of the bundle), `src/lib/chesspublica.ts`, game rendering in `src/components/ArticleBody.tsx`, or the diagram/comment
CSS in `src/site.css`. The note at the top of that file lists how this site differs from the old one.

## Rule: nothing in an article may be lost silently (new articles AND every new/edited game)
ChessPublica drops or mangles text it cannot parse, so every game that is added or edited goes through this checklist:
1. **`pnpm check:games`** (`scripts/check-games.mjs`; also run by `pnpm build`, `pnpm test` and the deploy workflow). It uses chess.js in
   *strict* mode (ChessPublica rejects redundant disambiguation such as `Nfd6` when `Nd6` is enough, and ambiguous `Ne2`) and fails on:
   an illegal move anywhere (main line, variations), unbalanced or nested `{ }` / `( )`, a `(12. Ne2 …)` line inside a comment that cannot be
   played from there (ChessPublica would delete it), a game header without movetext, `[Round "?"]`, `[#]` in a `<pgn>` game, and **move lines in
   comment prose that are not a real variation** (2+ numbered plies; book style `9 e5` without a dot counts too, and a `( … )`/`[ … ]` in the prose breaks a run). Genuine exceptions (move-order notes from the start position, threats, source
   typos waiting for the author) go in `scripts/check-games.allow.json` with a reason; never allowlist something that can be a variation.
2. **Every move that is playable from the position becomes a real variation** (exception: an article whose author wants each line written once, in the prose, gets a `linkedProse` entry in `scripts/check-games.allow.json`; its prose moves are made clickable in the study view instead, see the `[View "study"]` note) (`( 12. Ne2 f5 … )`, placed after the move it replaces and its
   comment; a continuation line goes after the *next* main-line move as an alternative to it). Keep the prose in the comment as well. Single
   numbered moves are only warnings (`pnpm check:games --warnings`), but convert them too when they are alternatives.
3. **`pnpm build && pnpm preview` then `pnpm check:render`** (`scripts/check-render.mjs`, Playwright; set `CHROMIUM_PATH=/opt/pw-browsers/chromium`
   in this environment) renders every published article and fails on `Error parsing PGN`, invalid moves or the red ⚠ marker. Look at the page, too.
4. ChessPublica itself must never delete content quietly: the patched bundle shows `⚠ Geçersiz hamle dizisi: …` (`<mark>`) for an unplayable
   inline line (see `docs/chesspublica-quirks.md`). If you find another place where it swallows text, patch it to show an error and add a check.
5. Check the prose too: move numbers must match the position (`12… ♗e6`, not `15. ♗e6`; `♘ge2` when both knights can go), and a line the
   author describes must actually be playable. Ask the author when the source text cannot be right.

ChessPublica `<pgn>` drops a comment placed before the first move, so `PgnGame` splits a leading `{ … }` off the movetext and shows it as a paragraph above the game (not for `<pgn-player>` games, where a leading `{[P]}` is the puzzle marker). Games need `[Round]` only for tournament lists: drop `[Round "?"]`, it would print “? . tur”. A PGN `Surname, Given` name is flipped, so write full given names.
- **Headings and paragraphs inside PGN comments** (`PgnGame` → `commentMarkup`, `sectionToc` in `ArticleBody.tsx`; Aronian article): in a `<pgn>` comment a line `### Title` becomes a heading (`<span class="cp-heading">`, styled like an article `###`, id = `slugify(title)`, listed in "İçindekiler" and reachable even before the game is mounted), and a blank line is a paragraph break (`<br><br>`). Blank lines inside `{ }` do not split the article into chunks (`src/lib/split-chunks.js`, shared with `check-games.mjs`; only for paragraphs that start like movetext). ChessPublica's sanitizer only keeps inline tags, so the bundle was patched (`pt` regex) to let `<span class="cp-heading">` through; the markup is added *after* HTML-escaping the PGN (`<pgn>` is read via `innerHTML`). Comments also take ChessPublica's inline Markdown (`**bold**`, `*italic*`, `` `code` ``, `[text](url)`). Only `<pgn>` (not `<pgn-player>`/`<pgn-study>`) draws the heading. A comment can also hold a photo: a line that is only `![alt](images/x.jpg "caption")` inside `{ … }` becomes an empty `<span class="cp-fig">` (also let through by the sanitizer patch) and `PgnGame` renders the normal `Figure` into it with a portal, so it looks exactly like an article photo (Keymer photo above "Problem taş" in the Aronian article).
- Markdown lists (`- …`) render with amber bullets (`ul` override in `mdOptions`).
- `<pgn>` only knows the `[D]` diagram marker (`[#]` is a `<pgn-player>` thing and would show as text), so write `{ [D] ... }` in article games. In `<pgn-study>` the `[D]` diagrams are hidden (`.pgn-clickable-diagram`, the study board already shows the position).
- Scroll: `history.scrollRestoration` is `manual` site-wide. The home page (`Index.tsx`) always opens at the top (reload, back/forward) unless the URL has a `#section` (`/#yazarlar`, the “abone ol” link in articles `/#bulten`): then it scrolls to that section (re-applied a few times while photos/diagrams settle, dropped when the reader scrolls; sections have `scroll-margin` so the fixed header does not cover their title); article pages (`Post.tsx`) remember the reading position per slug in `localStorage` (`scroll:<slug>`, saved only below 300 px; not saved once the article body's bottom edge is within 200 px of the viewport bottom, so a finished article reopens at the top) and re-apply it a few times while lazy photos/games settle; a `#hash` in the URL wins, and the user scrolling cancels the restore.
- YouTube videos (`<figure class="video-embed">` in `src/content/*.md`, `Video` in `ArticleBody.tsx`): `start`/`end` seconds are read from the embed address; every embed gets `rel=0&iv_load_policy=3&playsinline=1` (YouTube cannot hide the "More videos" strip shown on pause, `rel=0` only limits it to the same channel). A `data-poster="/images/…"` attribute on the `<figure>` shows our own cover image with a play button; the YouTube player is loaded (with `autoplay=1`) only when it is pressed (Mar del Plata: still of the documentary at 11:47).
- Highlighter emphasis: write `==text==` in `src/content/*.md` (article prose, blockquotes and `{ … }` game comments; `**bold**` stays bold and is used for names, labels and the Palavan interview questions). Drawn as a hand-drawn, slightly slanted yellow marker stroke (end of `src/site.css`: `--hl-1..3` are three irregular SVG strokes handed out by `:nth-of-type(3n+…)`, `box-decoration-break: clone` gives each wrapped line its own stroke; dark theme translucent gold with cream text, light theme brighter yellow with dark text). In prose markdown-to-jsx turns `==x==` into `<mark>`; in PGN comments `commentMarkup` turns it into `<ins>` (ChessPublica's comment sanitizer keeps `<ins>`; `<mark>` there is the red ⚠ error marker, so it is not used). Not handled: the leading `{ … }` comment shown as a plain paragraph above a game (`intro`).
