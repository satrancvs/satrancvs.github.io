# Satranç vs. (satranckahvesi.github.io)

React + Vite + Tailwind site, deployed to GitHub Pages from `main` (`.github/workflows/deploy.yml`) at the root of
https://satrancvs.com. Articles live in `src/data/articles.json` (metadata) and `src/content/*.md` (body).

## Read this before touching chess rendering
**`docs/chesspublica-quirks.md`** documents the undocumented ChessPublica behavior the old site (`satranckahvesi-eski`)
had to work around. Read it before changing anything that involves ChessPublica: `public/chesspublica/*` (a patched local
copy of the bundle), `src/lib/chesspublica.ts`, game rendering in `src/components/ArticleBody.tsx`, or the diagram/comment
CSS in `src/site.css`. The note at the top of that file lists how this site differs from the old one.

## Rule: nothing in an article may be lost silently (new articles AND every new/edited game)
ChessPublica drops or mangles text it cannot parse, so every game that is added or edited goes through this checklist:
1. **`pnpm check:games`** (`scripts/check-games.mjs`; also run by `pnpm build`, `pnpm test` and the deploy workflow). It uses chess.js in
   *strict* mode (ChessPublica rejects redundant disambiguation such as `Nfd6` when `Nd6` is enough, and ambiguous `Ne2`) and fails on:
   an illegal move anywhere (main line, variations), unbalanced or nested `{ }` / `( )`, a `(12. Ne2 …)` line inside a comment that cannot be
   played from there (ChessPublica would delete it), a game header without movetext, `[Round "?"]`, `[#]` in a `<pgn>` game, and **move lines in
   comment prose that are not a real variation** (2+ numbered plies; book style `9 e5` without a dot counts too, and a `( … )`/`[ … ]` in the prose breaks a run). Genuine exceptions (move-order notes from the start position, threats, source
   typos waiting for the author) go in `scripts/check-games.allow.json` with a reason; never allowlist something that can be a variation.
2. **Every move that is playable from the position becomes a real variation** (`( 12. Ne2 f5 … )`, placed after the move it replaces and its
   comment; a continuation line goes after the *next* main-line move as an alternative to it). Keep the prose in the comment as well. Single
   numbered moves are only warnings (`pnpm check:games --warnings`), but convert them too when they are alternatives.
3. **`pnpm build && pnpm preview` then `pnpm check:render`** (`scripts/check-render.mjs`, Playwright; set `CHROMIUM_PATH=/opt/pw-browsers/chromium`
   in this environment) renders every published article and fails on `Error parsing PGN`, invalid moves or the red ⚠ marker. Look at the page, too.
4. ChessPublica itself must never delete content quietly: the patched bundle shows `⚠ Geçersiz hamle dizisi: …` (`<mark>`) for an unplayable
   inline line (see `docs/chesspublica-quirks.md`). If you find another place where it swallows text, patch it to show an error and add a check.
5. Check the prose too: move numbers must match the position (`12… ♗e6`, not `15. ♗e6`; `♘ge2` when both knights can go), and a line the
   author describes must actually be playable. Ask the author when the source text cannot be right.

## Ported from the old Jekyll site (`satranckahvesi-eski`)
- `scripts/send-push.mjs`, `scripts/push/apps-script.gs`: new-article web-push notifications. Only these two are ported so
  far; the browser side (service worker, subscribe UI), the GitHub Action and the setup README still live in the old repo.
  Config is `push.config.json` (empty until notifications are set up).
- `src/lib/curly.js` (+ `tests/curly.test.js`) and `src/lib/curly-dom.ts`: curly quotes, em dashes and "1/2" → "½" for
  article prose and PGN comments (never move text). Run the tests with `pnpm test`.
  `keepEllipsisWithMove` (part of `toTypography`): Black's "…" / "..." never ends a line before its move (`…♘c6`, `12… ♗e6`): a space after it becomes a no-break space, no space gets a word joiner U+2060. Only before something that reads as a move, so ordinary prose with "…" still wraps; `study-fix.ts` accepts both characters between a move number and its move.
- Still to port if wanted: `scripts/check_content_links.rb`, `scripts/build-assets.mjs` (Jekyll-specific), other tests.
- `<pgn-player>` (puzzle view): `public/chesspublica/pgn-player.js` + `helpers.js`, `pgn.js`, `icons.js`, `board.js` are copied verbatim from ChessPublica's `assets/`; the bundle's own `<pgn-player>` definition was removed so the module can define it. Games with a `[P]`/`[Pn]` comment render as `<pgn-player>` (`PgnGame` in `ArticleBody.tsx`), others as `<pgn>`.
- `src/lib/localize-dom.ts` (port of the old `localize.js`): translates the player's hardcoded English UI strings (puzzle hint, "show solution", settings buttons). If ChessPublica changes those strings or class names (`.puzzle-hint-text`, `.puzzle-hint-btn`), update it. The old "Puzzle solved!" patch is not ported: this `pgn-player.js` has no such string.
- Article photos use `src/components/ProgressiveImage.tsx` (blurred LQIP + reserved space, fades in on load). Sizes and placeholders live in `src/data/image-meta.json`.
- **Photo standard** (`scripts/imgstd.py`, `scripts/optimize-images.py`, Pillow; shown by `ProgressiveImage.tsx`): every article photo is displayed in one of three fixed boxes, so photos are the same size across all articles: **horizontal (`h`) 3:2, 600 × 400 px** (file ≤ 1200 × 800), **vertical (`v`) 2:3, 400 × 600 px** (file ≤ 800 × 1200), **small (`s`) 2:3, 240 × 360 px** (file ≤ 480 × 720; book covers and low-resolution portraits). The class is derived from the file (cover name → `s`; wider than tall → `h`; portrait → `v`, or `s` when the 2:3 crop has less than 1.5× the display size, i.e. under 600 × 900); low-resolution *landscape* photos are rejected. After adding a photo to `public/images/` run `python3 scripts/optimize-images.py`: it crops the file to the exact ratio (only the surplus, from the centre; `scripts/image-focus.json` `{ "file.jpg": [x, y] }` picks what to keep), shrinks it if it exceeds the 2× size, never upscales, JPEG quality 82, and refreshes `image-meta.json` (size, `kind`, blurred placeholder). Files that already fit are not touched; `--check` only reports (non-zero exit when something does not fit). Photo captions/credits (`.credit`), video captions, the game loading text (`.cp-loading`), the home-card diagram caption and the cover credit are mono ALL-CAPS: wrap foreign names/titles with an `i` in `<span lang="en">…</span>` (nl, de, …; otherwise Turkish uppercase gives `İ`), and wrap move notation in `<span class="keep-case">…</span>` (the diagram caption `17... Rxg5!!`). Cross tables (`.crosstable`) and the a1/b2 list labels stay as they are. Small-class captions may be wider than the photo (figure up to 480 px, centred). Aim for the least cropping: shoot/choose photos close to 3:2 or 2:3. Photos are shown in grayscale by default (book covers are colour); contemporary colour photos listed in `scripts/image-color.json` (`salon.jpg`, `piramit.jpg` in the Karlsruhe article) stay in colour (`color` flag in `image-meta.json`).
- Home-page card thumbnails (`thumb` in `articles.json`) are always a 3:2 box at column width, centre-cropped whatever the photo's ratio (`thumb` mode of `ProgressiveImage`); `thumbPosition` (CSS `object-position`, e.g. `"50% 20%"`) picks what to keep when a portrait photo is cropped.
- `src/lib/inline-play.ts`: moves the player's comment play button into the last line of the comment text (inline). Comments with variations keep it below. Depends on `.video-comment > .comment-play-btn` and `.comment-body` in `pgn-player.js`.
- Book covers live in `public/images/` with `adventurous-way` or `chess-for-zebras` in the name are shown small and in color (`cover` mode in `ProgressiveImage`/`Figure`); other photos are grayscale.
- Game titles: ChessPublica's own title blocks (`.video-title`, `.pgn-headers`) are hidden; `GameSection` in `ArticleBody.tsx` shows the round heading (round, players, result) for games with a `[Round]` tag (tournament lists such as the Timman article); games without `[Round]`, and the `[View "player"]` section, show two centred lines instead: players with Elo (`Given Surname`, a PGN `Surname, Given` is flipped) and `Event, Site, year`. A game can override that second line with an `[EventLine "…"]` tag (inline Markdown/HTML such as `<i>` is allowed; the tag is not passed to ChessPublica): the Monarch Assurance game uses it.
- `src/lib/variation-fix.ts` (port of the old `variation-fix.js`, without the Space autoplay): clicking a move inside a variation makes `pgn-player` rebuild the comment box and drop the variation lists/mainline comment; this puts the live nodes back, fixes the active-move highlight and handles switching between variations. Relies on `player._engine` / `_variation` internals.
- Games mount lazily (`PgnGame` in `ArticleBody.tsx`: IntersectionObserver, 1500 px ahead; everything mounts at once when the URL has a `#hash`). Raw PGN text is hidden by CSS until ChessPublica has rendered it; later-mounted `<pgn>` elements are picked up by calling `initAll()` again.
- Adding an article: append an entry to `src/data/articles.json` (`date`, e.g. "Ekim 2026", is required: cards, the list and the cover show it next to the category; the article page shows the category above the title and one byline row under the dek: author, "Türkçesi: …" when there is a translator, then the date, joined by middots; the dek/excerpt under the title is plain Manrope body text; there are no reading times; optional `authorLabel` replaces the "Yazar" word before the name (e.g. "Anket: Eugen Gömöri"; article header and cards), optional `translator` shows "Türkçesi: …" in the byline), put its body in `src/content/<name>.md` and register it by id in `CHUNKS` in `src/data/articles.ts`. Authors listed under "Katkıda bulunanlar" live in `AUTHORS` in `src/pages/Index.tsx`. `bio` (inline Markdown, so it can hold links) and `count` (`true` = counted from the articles, a number = shown as is; Nazmi Can Doğan 3 and Oğul Köseoğlu 2 are fixed numbers set on request) are optional per author. List labels (a1, b2, …) wrap after h8 (the ninth article is a9). The "Tüm yazılar" list order is `LIST_ORDER` (ids) in `src/data/articles.ts` (`LISTED`); the cover and "Öne çıkanlar" follow `articles.json` order instead. A new article missing from `LIST_ORDER` goes to the end of the list; add its id where it should appear.
- Curly quotes also apply to article titles/deks/excerpts: `articles.ts` runs `toTypography` over them and `vite.config.ts` does the same for `<title>` and meta descriptions, so straight quotes in `articles.json` are fine.
- A PGN header with `[View "player"]` renders that game as `<pgn-player>` even without a `[P]` marker (the tag is stripped before it reaches ChessPublica), and its `GameSection` shows no round heading (used for the "watch the game" copy at the end of the Muğla article). The table of contents appears only with two or more `###` headings.
- Inline diagrams in `<pgn>` (ported from the old `diagrams.css`, rules in `src/site.css`): in this ChessPublica build they are `.jc-board-wrapper` (chessboard.js, sized from the wrapper's width when drawn), not `.cp-board-wrapper` as in the old bundle. Mainline diagrams are `min(400px, 94cqw)`, diagrams inside a variation are 3rem smaller and paler, nested variations 6rem; `.gm-badge` scales with the wrapper via `--dw`. Needs `container-type: inline-size` on `.cp-game .pgn-container` for `cqw`.
- A last paragraph starting `Devamı gelecek.` (Karlsruhe, At ve fil) is drawn as a separate closing block (`Continued` in `ArticleBody.tsx`, `.to-be-continued`: centred label between two rules, the newsletter link as an outlined pill; the trailing full stop is dropped).
- The Karlsruhe article ends with a `### Oyunu inceleyin` heading and a `[View "study"]` copy of the game (header repeated, no movetext) before the "Devamı gelecek" line.
- `[View "study"]` renders the game as `<pgn-study>` (long commentary: board on top, prev/next/download/flip bar, scrolling move + comment list below), one column below 56em and two columns from 56em up (left: board + button bar, right: scrolling move/comment list; the frame breaks out of the text column, `min(62rem, 100vw − 3rem)`). The frame (`.study-frame`, the game's `GameSection`) holds the game title (players, event) and the panel inside one border; rules at the end of `src/site.css`. The study board is the same size as an inline `<pgn>` diagram (`min(400px, 94cqw of the article column)`; the panel has no side padding on narrow screens so it fits). `public/chesspublica/pgn-study.js` (+ `init.js`, and a `puzzle.js` stub: **no puzzles in a study**, `[P]` markers are stripped) is loaded only by articles with a study (`loadStudy` in `src/lib/chesspublica.ts`). Patches to the upstream file: the opening table of contents (`buildOpeningToc`) is not called. `src/lib/study-fix.ts` (port of the old `_js/chesspublica/study/`): removes play/TOC/article/speed/settings/collapse buttons, adds prev/next, turns autoplay off, arrow-key stepping, branch picker auto-resolve, keeps the panel from collapsing. It relies on `player._engine`, `_loopRAF`, `_variationPlayTick`. A `### Oyunu inceleyin` heading goes right before every study (like `### Oyunu izleyin` before the Muğla player). Move lines written in mainline comment prose (`2. ♘c3 … 2… ♗b4 …, 3. ♘d5 ♗e7`) become clickable in the study (`linkProseMoves` in `study-fix.ts`: replayed from the commented position with chess.js; a legal run is split into `.pgn-move.cp-prose-move` spans with `data-fen/from/to`, which the study's own click handler shows on the board; a number marker that is the next move of the same line continues it across prose). So an author who wants only the prose, without a duplicate `( … )` variation, can drop the variation and allowlist the prose run in `scripts/check-games.allow.json` (done for the Karlsruhe 2.Nc3 Bb4 line and seven more variations whose moves are fully written in the preceding comment; variations with their own comments or nested lines stay). A prose line starts from the position after the commented move, or from the one before it (it may be an alternative to that move). One study per page (the upstream module looks elements up by id). It counts as the "watch" copy for the text game's “Oyunu izle ↓” button, same as `[View "player"]`.
- A text game (`<pgn>`) that has a `[View "player"]` copy later in the same article (same White/Black/Date/Round, `key` in `GameItem`) gets an “Oyunu izle ↓” button under its title (`GameSection`) that smooth-scrolls to the player section (Muğla article). The button reads “Oyunu incele ↓” when the copy is a `[View "study"]` (Karlsruhe), and when a `###` heading (“Oyunu izleyin” / “Oyunu inceleyin”) sits right before that copy it scrolls to the heading instead of the section.
- A `[View "player"]` header with no movetext after it reuses the movetext of the earlier game in the same article with the same White/Black/Date/Round (`gameMoves` in `ArticleBody.tsx`), so the PGN is written once (Muğla article). If no earlier game matches, or the next paragraph starts with a move number or `{`, the old behavior (next paragraph is the movetext) applies.
- Home-page card diagram: an article in `articles.json` with `diagram` (a FEN) and optional `diagramAlt` shows a static ChessPublica `<fen>` board below the card text (category · date, title, dek, byline) in "Öne çıkanlar" (`src/components/FenDiagram.tsx`, rules in `src/site.css`). ChessPublica is loaded only when the card nears the viewport (`useChessPublica`); a square placeholder reserves the space. On mobile the board is a `max-width: 400px` square; from `md` up the first card passes `fill`: the card stretches to the grid rows (it is `row-span-2`) and the board is drawn as a square of `min(box width, box height)`, so the left card ends level with the two right cards. The box content is absolutely positioned so it never inflates the rows, and `<fen>` is re-created (key) when the size changes, because ChessPublica sizes the board from the container width at draw time.
- **Rule: the home-page diagram plus its caption never exceeds the screen height** (fixed header subtracted, 16 px margin). `FenDiagram` measures `header` and the caption and sets `--fen-cap` on `.fen-diagram`; the CSS `max-width` is `min(400px | 515px, var(--fen-cap))`. The desktop board is otherwise 515 px (`.fen-fill`).
- Unpublished (`"draft": true`) articles in `articles.json`: shown only as a non-clickable card in "Öne çıkanlar" (`Index.tsx`). They have no page (`articleBySlug` ignores them, so the URL is the 404 page), no prerender or sitemap entry (`vite.config.ts`), no place in the "Tüm yazılar" list, tabs or author counts (`PUBLISHED` in `articles.ts`) and no push announcement (`newArticles` in `scripts/send-push.mjs`; it counts as new the day `draft` is removed). The author card counts articles the person wrote or translated (`translator`; Tarık Selbes: Karlsruhe + Gömöri = 2). An author whose only articles are drafts shows "Yakında" instead of "0 yazı" on the author card (`authorCount` in `Index.tsx`). `titleLines` splits a card title in two lines, the second in amber italic. `diagramOrientation: "black"` draws the card diagram from Black's side; `diagramCaption` is the left-aligned line under it (the board sits at the left of its box). `diagramBadge` (`{ "square": "a5", "glyph": "!?" }`) draws a move-quality badge on a square: the static `<fen>` has none, so `FenDiagram` overlays its own `.gm-badge` (same colours, 0.055 × board size) at the square's top-right corner. `diagramArrow` (`{ "from": "a8", "to": "a5" }`) overlays a grey, half-transparent arrow (the last move) from the centre of one square to the other. Moves written in the caption/alt with English piece letters (`Ra5`) are turned into figurines (`♖a5`) by the ChessPublica bundle; Turkish letters collide (`K` would become the king).
- Blockquotes (`> …` in `src/content/*.md`) render as a dark box with a corner quote mark (`.quote` in `src/site.css`, `Quote` / `QuoteWithFigure` in `ArticleBody.tsx`). Every quote ends with a source line: a last paragraph starting with `— ` becomes the mono `.quote-cite` footer. The source line may hold inline HTML: wrap foreign names/titles in `<span lang="en">…</span>` (or `de`, `nl`, …), otherwise the uppercase mono style turns their `i` into Turkish `İ` (Steinitz → STEİNİTZ). A ` · ` inside the source line becomes a line break (`citeLines`; Frost poem: translator on the second line). A quote that contains a photo keeps the `![…](…)` line inside the `>` lines (Korchnoi quote in the Zebras article): the photo renders inside the box and the source appears once at the end.
- Leading marker lines in a blockquote (not rendered): `> [sağa yaslı]` right-aligns it (`.quote-right`), `> [şiir]` sets its text in Fraunces italic (`.quote-poem`); both on the Frost poem in the Karlsruhe article and the Sufi saying (“Toynak sesi duyunca…”) in the Zebras article.
- Static diagrams in article text: a paragraph that is only `[FEN "…"]` is a centred `<fen>` board (a study); a `> [FEN "…"]` line inside a blockquote becomes a `<fen>` board (`FenBlock` in `ArticleBody.tsx`, `.art-fen`, centred, ≤ 340 px; a `(crop: top-half)` suffix after the FEN line shows only ranks 8–5). A non-player `<pgn>` game that starts from a `[FEN]` (SetUp) also gets its start position as a `FenBlock` above the moves (`<pgn>` draws no start diagram). ChessPublica `<pgn>` drops a comment placed before the first move, so `PgnGame` splits a leading `{ … }` off the movetext and shows it as a paragraph above the game (not for `<pgn-player>` games, where a leading `{[P]}` is the puzzle marker). Games need `[Round]` only for tournament lists: drop `[Round "?"]`, it would print “? . tur”. A PGN `Surname, Given` name is flipped, so write full given names.
- Markdown lists (`- …`) render with amber bullets (`ul` override in `mdOptions`).
- `<pgn>` only knows the `[D]` diagram marker (`[#]` is a `<pgn-player>` thing and would show as text), so write `{ [D] ... }` in article games.
- Scroll: `history.scrollRestoration` is `manual` site-wide. The home page (`Index.tsx`) always opens at the top (reload, back/forward); article pages (`Post.tsx`) remember the reading position per slug in `localStorage` (`scroll:<slug>`, saved only below 300 px) and re-apply it a few times while lazy photos/games settle; a `#hash` in the URL wins, and the user scrolling cancels the restore.
